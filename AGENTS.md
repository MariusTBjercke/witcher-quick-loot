## Project at a glance

A mod for The Witcher: Enhanced Edition 1.5 that adds a hotkey (default Space). In the loot window it presses **Take all**; in a shop or storage it does nothing; anywhere else it performs Space's normal pause toggle. A bound key never reaches the game, so the mod has to do that last part itself.

| Path | What |

## Build, test, release

- **Change behaviour:** edit `QuickLoot_TakeAllOrPause()` in `quickloot_hook.lua` and restart the game. No compile is needed.
- **Rebuild the script** (only if the Lua function name changes): `python -I tools\build_lootall_ncs.py mod\Data\Override\QuickLoot\lootall.ncs`. The game's own compiler also works (`ENABLE_CONSOLE = true`, then `compile ..\Data\Override\QuickLoot\lootall.nss` in the console), but check where the `.ncs` lands. It once ended up in `Data\Override\` instead of next to the source, and a stray copy there also loads.
- **Test** from a clean install of the zip with no `System\keybinding.ini`. Space in the loot window takes all. Space in a shop does nothing. Space elsewhere pauses (with the pause menu), and Space again unpauses. All three were confirmed in game for 1.0.1.
- **Package and release:** `powershell -File tools\package-release.ps1`, then `gh release create vX.Y.Z dist\WitcherQuickLoot-X.Y.Z.zip ...`.

## Findings

- The loot window is the inventory panel in transfer mode: `g_GuiInGame.lm_pNewInventoryPanel`, in `System\Scripts\gui_new_inventory.luc`. Its sub-panel `lm_pTransferPanel` (`CGuiNewTransferPanel`) has `TransferAll()`. That function calls `g_GuiInGame:Inv_TransferAllItemsToPlayer(container, skinning)` and equips what fits, and it is what the **Take all** button ends up calling. The path is `gui_defs_inv_v2.luc` → `OnClick = g_GuiLayoutManager:PerformButtonAction('TransferAllButton')` → a closure that calls `transferPanel:TransferAll()`.
- `CGuiNewInventoryPanel:IsLootOpen()` compares a file-local transfer status with `TRANSFER_STATUS_LOOT`. The other statuses are `NONE`, `STORE`, `STORAGE` and `TRANSFERALL`, so checking it keeps the hotkey out of shops and storage. `lm_bActive` tells whether the inventory is open at all.
- `gui_new_inv_autoloot.luc` (`lm_pNewInvAutoLootPanel`, `Inv_AutoTransferAll`) is a different, timed auto-transfer panel. It is not the window with the button.
- Key macros (`bindkey`) still fire while the inventory GUI is open. This was confirmed in game.
- **A bound key is swallowed.** `FUN_004262f0` handles every input event. It first calls `FUN_0041ea20` (the macro lookup). When that finds a binding, it runs it and returns 1, and the event is **not** passed on to the normal handler `FUN_00423bd0`. There is no pass-through. Space's pause is not in the registry `Bindings` (it is hard-wired), so it looked like a free key. That broke pause in 1.0.0.
- **Pause:** in `FUN_00423bd0`, action `0x60` (Space) calls `FUN_0041bdc0` → `FUN_00429630` → `FUN_00429210(6, 0x18, 0, 0)`, the toggle-pause request to the internal server. Lua reaches the same path through `CClientExoApp:TogglePauseRequest()` (binding `FUN_006131e0` → `FUN_00402ac0` → `FUN_0041bdc0`); the instance is `g_pClientExoApp`. Lua is told afterwards through the GUI events `pause.on` / `pause.off` (`gui.luc`), which show the pause panel and set `g_GuiInGame.lm_bUserPause`. `g_GuiInGame:SendSetPauseState(type, bPause, bFlag)` (`FUN_004448a0`, message 8/4) is a different, absolute set-pause path, used to cancel pause in dialogs. Do not use it for the user pause.
- `QuickLoot_TakeAllOrPause()` only pauses when `not g_GuiInGame:IsAnyPanelOpen()`, matching the vanilla key, which skips pause while a modal GUI is up. It always unpauses when `lm_bUserPause` is set.

## Shared loader rules

- `mod/System/Scripts/testtools.lua` must stay **byte-identical** across all mods that ship it. The game's Lua cannot list a folder (there is no `CFileFind` or directory binding), so the loader names every hook in `HOOKS`. A new mod that uses the loader adds its hook name there; then bump the "loader version" comment and release every mod that ships the loader.
- In a hook's settings, `false` unbinds a key. `nil` drops the entry from the table, so a previous binding is never cleaned up.
